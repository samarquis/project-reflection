# Self-review procedure

Measure learning-system effects, not report volume.

## Evidence

Use event histories, deep reports, lesson registry, effectiveness ledger, current skill files, eval spec/results, and user corrections. Missing trigger telemetry and unavailable chats remain gaps.

## Checks

1. Compare meaningful project events with reflection notes; list missed and duplicate triggers.
2. Trace every active lesson: retrieved, applied or rejected, predicted effect, observed effect, and last validation.
3. Recheck promotions for overfitting, semantic duplicates, canonical-owner conflicts, and later contradiction.
4. Sample success, failure, improvement, causal, and perfection claims against evidence.
5. Inspect whether notes caused concrete changes or merely accumulated text.
6. Review activation and mode-selection errors, including work belonging to a specialist skill.
7. Score with `quality-rubric.md` and propose smallest measurable change.

## Output

Record scope, evidence coverage, trigger precision/recall when measurable, lesson effectiveness, defects, proposed change, before/after eval evidence, quality assessment, and next review condition. Keep proposed changes separate from authorized edits.

A skill change succeeds only when deterministic checks pass and evaluation improves or preserves required behavior without new regression. If eval harness fails before execution, record `unverified` and keep change open.
